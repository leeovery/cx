- FINDING: `internal/hooks` spells its one on-disk shape three different ways across its exported API
  SEVERITY: medium
  FILES: internal/hooks/store.go:29, internal/hooks/store.go:42, internal/hooks/store.go:273, internal/hooks/store.go:279, cmd/doctor.go:305, cmd/doctor.go:313
  DESCRIPTION: `map[string]map[string]string` — the hooks.json body — appears under three names on the package's public face. `hooksFile` is an unexported alias, and the exported `Load(via Via) (hooksFile, error)` returns it, so godoc and every reader of the signature see an identifier they cannot name or follow. `Snapshot` is an exported *defined* type for the identical shape, taken by the exported `CleanStale` callback. And `StaleKeys` spells the raw map literally — it had to, because the alias it would naturally use is unexported. The consequence is visible at the one call site that uses two of them together (`cmd/doctor.go`: `store.Load(...)` feeding `hooks.StaleKeys(...)`): the value flows fine because the alias is transparent, but nothing in the signatures tells the reader these are the same thing, and a future change from alias to defined type would break that call silently-at-compile-time for no design reason. One package, one concept, one name is the expectation here — the boundary currently makes the caller reconstruct that fact.
  RECOMMENDATION: Name the shape once as an exported defined type (reuse `Snapshot`, or introduce `Entries` and make `Snapshot` its documented alias-for-role) and use it in `Load`, `StaleKeys`, `CleanStale` and the unexported `load`/`save`/`staleKeys` helpers. `Load` in particular must stop returning an unexported identifier.

- FINDING: `cmd` now carries two opposing `*Deps` merge conventions, and the older one fails silently with no completeness guard
  SEVERITY: medium
  FILES: cmd/hooks.go:83, cmd/doctor.go:74, cmd/doctor.go:104, cmd/state_commit_now.go:49
  DESCRIPTION: This work introduced `hookSeams()`, which starts from whatever the test injected and *fills in* the production default per unset seam. A field added to `HooksDeps` without a fill line is a nil dereference — loud, immediate, unmissable. The two sibling resolvers it now sits beside, `resolveDoctorDeps` and `resolveCommitNowDeps`, run the opposite direction: build production defaults, then overwrite field-by-field from the injected struct (`if doctorDeps.X != nil { deps.X = doctorDeps.X }`, eleven times in `resolveDoctorDeps`). A field added to `DoctorDeps` or `CommitNowDeps` without its matching override line is silent — the test's mock is ignored and the production default runs, and nothing anywhere fails. Two conventions for one job in one package is the drift risk; the fail-silent direction being the un-guarded one is the sharper half. The package already guards *how* seams are installed (`cmd/deps_seam_guard_test.go` reads the seam set out of the production sources rather than listing it) and the repo already uses reflection-based struct-field completeness guards elsewhere (`internal/theme/theme_test.go:97`, `cmd/doctor_advisory_test.go:52`), so the missing piece is a field-count/field-name guard over the override chains — or, better, converting them to `hookSeams`'s direction so the compiler holds the invariant instead of a test.
  RECOMMENDATION: Pick one direction for the whole package. Preferably convert `resolveDoctorDeps` / `resolveCommitNowDeps` to the fill-in-defaults shape `hookSeams` established, so a forgotten seam cannot be silently ignored. If they must stay as overwrite-merges, add a reflection guard asserting every exported field of each `*Deps` struct is named in its resolver, in the style of the existing theme field guards.

- FINDING: `logtest.Sink` exposes a query cross-product because the composable filters were closed off
  SEVERITY: low
  FILES: internal/logtest/capture.go:110, internal/logtest/capture.go:218, internal/logtest/capture.go:248, internal/logtest/capture.go:255
  DESCRIPTION: `Records` has four filter methods — `atExactLevel`, `atOrAboveLevel`, `withMessage`, `matching` — all unexported, with the stated rationale that a caller must never have two ways to ask one question. The cost is that every *combination* of those orthogonal dimensions needs its own exported `Sink` method, and two already exist purely as one-line compositions of others (`RecordsAtExactLevelWith` = `RecordsWith(...).atExactLevel(...)`, `RecordsAtExactLevelWithMessage` = `RecordsWithMessage(...).atExactLevel(...)`). The surface is at seven `Records*` methods for two-and-a-bit dimensions and grows multiplicatively: the next axis (attr predicate, say, or component-without-message) doubles it rather than adding one. The single-route property that motivated the closure is worth keeping, but it is achievable by exporting the orthogonal filters and *not* exporting combinations, rather than by exporting combinations and not filters.
  RECOMMENDATION: Export the four `Records` filters and keep only the base `Sink.Records()` (plus the `OnlyRecord*` assertions, which do more than filter). Callers then compose the one route per question themselves; the combination methods disappear rather than multiplying.

- FINDING: the general-purpose `TestingT` subset has two homes, and non-logging test packages import `logtest` to reach one of them
  SEVERITY: low
  FILES: internal/logtest/capture.go:23, internal/sourceguardtest/packagedeps.go:11, internal/hookstest/hooks.go:102, internal/hookstest/hooks.go:118, cmd/deps_seam_guard_test.go:44
  DESCRIPTION: `TestingT` — the "subset of `*testing.T` a fatal-on-failure helper needs, so the helper's own failure path is testable" — is declared independently in both `internal/logtest` and `internal/sourceguardtest`. Neither declaration has anything to do with logging or with source scanning; it is a general test-scaffolding primitive. The result is that `internal/hookstest`, whose whole subject is hooks.json bytes, takes a dependency on the *logging* capture package for two byte-comparison helpers, and `cmd`'s source-scanning seam guard does the same for a function that parses Go files. The package edges misdescribe what depends on what, and the duplicate declaration means the two copies can drift in which methods they require.
  RECOMMENDATION: Home `TestingT` once — either in a neutral test leaf or in `sourceguardtest`, which is already the stdlib-only shared-primitives package — and have `logtest` and `hookstest` reference that one declaration, so no package imports a logging helper for a type unrelated to logging.

- FINDING: the stale sweep enumerates every pane on the server before checking whether there is anything to sweep
  SEVERITY: low
  FILES: cmd/run_hook_stale_cleanup.go:207, cmd/run_hook_stale_cleanup.go:221
  DESCRIPTION: `liveTokenEnumeration` runs `judgeAgainstLivePanes` — a whole-server `list-panes -a -F` — and only afterwards short-circuits on `len(snapshot) == 0`. The comment on that short-circuit reasons carefully about the cost it avoids (creating the config directory, creating the sidecar, taking an exclusive hold) but the tmux read it has already paid is the most expensive step of the three, and on an install that has never registered a hook it can change nothing: with an empty snapshot there is no key to judge and no key to protect, whatever the enumeration returns. The daemon pays it every 10s for the lifetime of the process. The cheapest and most decisive test is ordered last.
  RECOMMENDATION: Take the `len(snapshot) == 0` branch before the enumeration, and either drop the counts DEBUG for that case or emit it with the entry count alone — the pane count has nothing to report about a cycle that was never going to judge anything.
SUMMARY: The core of the change composes well — the staleness rule has one home that every reader routes through, the pane-token option literal has one declaration, `internal/hooks` is guarded as a genuine leaf, and the restore/sweep/diagnosis seams share their stand-down decision rather than restating it. What is worth restructuring is at the edges: `internal/hooks` presents one data shape under three names on its public face, and the `cmd` package now runs two opposite `*Deps` merge conventions with the fail-silent one left unguarded.
