- FINDING: The `on-resume` event name is an untyped magic string, and the store now reaches for it internally
  SEVERITY: medium
  FILES: internal/hooks/store.go:354, internal/hooks/lookup.go:25, internal/hooks/store.go:113, internal/hooks/store.go:163, cmd/hooks.go:219, cmd/hooks.go:293, internal/hookstest/staging.go:130, internal/hookstest/hooks.go:79
  DESCRIPTION: `Store.Set(key, event, command, via)` and `Store.Remove(key, event, via)` model the event dimension as a caller-supplied plain `string`, and the only value ever passed anywhere is the literal `"on-resume"` — spelled at eight sites, two of them inside `internal/hooks` itself. This work unit added the worst of them: `deleteStale`'s new audit line sources its `value` attr with `h[key]["on-resume"]`, so the store hardcodes one event to read a map whose whole shape exists to be event-generic. An entry persisted under any other event would be deleted and logged with an empty `value` — the exact "what did I lose?" line §5.3 exists to make recoverable, silently wrong. The inconsistency is sharpest against `Via`, which this same work unit gave a closed integer enum for a strictly weaker reason ("a caller cannot pass an invented literal that compiles and then produces a log attr no search will ever match"). The event string is not a log attr — it is the second-level key into persisted state, where an invented literal writes an entry nothing will ever fire. The stronger type went to the weaker concept.
  RECOMMENDATION: Give the event the same treatment `Via` got: a `hooks.Event` type (or at minimum an exported `hooks.EventOnResume` constant) that `Set`, `Remove` and `LookupOnResume` take, so the vocabulary is closed at the boundary and spelled once. Separately, stop `deleteStale` reaching into the map for one event name: have the removal record carry the removed entry's events (the pre-delete map `h` is already in hand), so the audit line reports what was actually removed rather than what the store assumed was there.

- FINDING: One sweep cycle's log lines are split across three components by an injected logger
  SEVERITY: medium
  FILES: cmd/run_hook_stale_cleanup.go:141, cmd/run_hook_stale_cleanup.go:252, cmd/run_hook_stale_cleanup.go:288, cmd/state_daemon.go:211, cmd/doctor.go:200
  DESCRIPTION: `runHookStaleCleanup` now emits one cycle's output through two different loggers by design: every stand-down goes out under the `hooks` component via `standDown.emit()`, while the cycle's two DEBUG counts go to whatever `countsLogger` names — `daemon` from `maybeRunHookCleanup`, `bootstrap` from `pruneDoctorStaleHooks`. A third slice escapes both: an unclassified sweep error is worded by each caller separately (`daemon: hooks stale-cleanup failed`, `bootstrap: doctor --fix: stale-hook prune failed`). The pre-change function emitted its whole cycle through the one injected logger, so this scattering is newly introduced. The function's own doc comment names the consequence — "a caller observing this cycle through countsLogger alone sees the counts and none of the stand-downs" — which is precisely the property this work unit exists to remove: the loss was silent because reconstructing one cycle required correlating across sources. An operator now needs three greps (`hooks:`, `daemon:`, `bootstrap:`) to reconstruct one 10s sweep, and the closed `clean-stale-skipped` vocabulary built to make declines identifiable covers only the subset that routes through `emit()`.
  RECOMMENDATION: Drop the `countsLogger` seam and emit the whole cycle — counts, stand-downs and failures alike — under `hooks`, the component that owns the subsystem being swept. The two callers keep whatever cycle-summary line their own component owes (`bootstrap: orchestration complete`-style), but stop wording the sweep's internals in their own vocabulary. That makes `grep 'hooks:'` reconstruct one cycle whole, which is the stated goal.

- FINDING: The sweep reads `hooks.json` twice; only one read's failure has a reason
  SEVERITY: low
  FILES: internal/hooks/store.go:305, internal/hooks/store.go:330, cmd/run_hook_stale_cleanup.go:305
  DESCRIPTION: `CleanStale` classifies its advisory pre-read failure as `ErrSnapshotRead`, which `declinedSweep` maps to `store-read-failed`. But `deleteStale` performs a second `s.load()` of the same file under its exclusive hold, and that failure is wrapped as a bare `fmt.Errorf("failed to load hooks: %w", ...)` with no sentinel — so it falls through `declinedSweep`'s switch to the unclassified default and leaves the closed reason vocabulary entirely, reported instead by whatever words the caller happens to hold. The same file, failing to read for the same reason, is identifiable in one phase and anonymous in the other. This undercuts §5.4's premise that "every decline is identifiable rather than only the three the guard cases cover".
  RECOMMENDATION: Wrap `deleteStale`'s load failure in the same `ErrSnapshotRead` sentinel (or a sibling `ErrStoreRead`) so both reads of `hooks.json` classify to `store-read-failed`, and leave only genuine save failures on the unclassified path where `sweep-failed` already covers them.

- FINDING: The stand-down reason vocabulary is guarded three ways and carries members no surface can reach
  SEVERITY: low
  FILES: cmd/run_hook_stale_cleanup.go:22-100, cmd/doctor_stand_down_phrase_guard_test.go:47-116, cmd/doctor_stand_down_copy_test.go:54-59
  DESCRIPTION: Seven `skipReason` constants are backed by two exhaustive phrase maps, an enumerable `skipReasons` slice, an AST guard proving the slice matches the const block, a coverage guard proving both maps are exhaustive and carry no extras, a copy-uniqueness guard with a `notStandDownReasons` subtraction list, *and* a runtime fallback in `phraseFor` that returns the raw reason for an unmapped one. The exhaustiveness guard makes `phraseFor`'s fallback unreachable; the fallback makes the exhaustiveness guard optional. Meanwhile the vocabulary itself is not internally consistent: `notEvaluableDetails[skipReasonLockTimeout]` is documented in-source as unreachable and present "for vocabulary completeness", and `skipReasonSweepFailed` is a member of a type whose own doc calls it "the closed vocabulary of reasons a cycle removed nothing" and whose log op is `clean-stale-skipped`, yet it is never a skip and never logged — which is why the copy guard has to subtract it back out. That is copy authored for combinations that cannot occur, then pinned in place by a test.
  RECOMMENDATION: Pick one enforcement — keep the exhaustiveness guard and delete `phraseFor`'s fallback branch (an unmapped reason then fails a test rather than printing a raw token), or keep the fallback and stop demanding exhaustiveness for reasons a given surface cannot reach. Separately, either move `skipReasonSweepFailed` out of `skipReason` (it is a failure the `--fix` renderer reports, not a stand-down) or rename the type to cover both, so the guard no longer needs a subtraction list to compensate for a member the type's contract excludes.

- FINDING: `internal/hooks`'s read API is inconsistent across its three read entry points
  SEVERITY: low
  FILES: internal/hooks/lookup.go:14, internal/hooks/store.go:42, internal/hooks/store.go:249
  DESCRIPTION: The package now offers three ways to read, each shaped differently. `Load(via)` and `List(via)` are methods taking the caller's `Via`. `LookupOnResume(store, hookKey)` is a package-level function taking `*Store` as its first parameter and hardcoding `ViaHydrate` internally — so the one read whose caller is fixed is the one that does not take the parameter, and it is a free function where its siblings are methods despite reaching an unexported method on the receiver it is handed. `StaleKeys(persisted, live)` is an exported function whose entire body is `return staleKeys(persisted, live)` with an identical signature — an exported/unexported twin pair where one export would do. The result is a public surface where the shape of a call carries no information about what it does.
  RECOMMENDATION: Make `LookupOnResume` a method on `*Store` taking a `Via` like its siblings (`ViaHydrate` then comes from the one caller that means it), and collapse the `StaleKeys`/`staleKeys` pair to the single exported function `deleteStale` and `checkStaleHooks` both call.

- FINDING: The hook-staleness cycle is a self-contained domain living in `cmd`
  SEVERITY: low
  FILES: cmd/run_hook_stale_cleanup.go:1-345, cmd/doctor.go:196-217, cmd/doctor.go:292-337
  DESCRIPTION: `cmd/run_hook_stale_cleanup.go` grew from ~60 lines to 345 and now holds five types (`skipReason`, `standDown`, `stalenessView`, `sweepOutcome`, `declinedError`), a closed reason vocabulary, two user-facing copy tables, and the emission policy for a subsystem — none of which is cobra-shaped. Its copy tables sit in this file while both renderers that consume them (`reportSkippedPrune`, `staleHooksNotEvaluable`) live in `doctor.go`, and its component binding is borrowed from `cmd`'s `hooksLogger`. It is reached by exactly two callers, both of which pass it a seam interface rather than a command. The seam works and the pieces compose, but the policy has outgrown the package it sits in, and its home is the reason the component split in the second finding above was reachable at all.
  RECOMMENDATION: Consider lifting the cycle into its own package (the reason vocabulary, `standDown`, `stalenessView`, `sweepOutcome` and `runHookStaleCleanup`) with its own `hooks` component binding, leaving `cmd` holding only the two call sites and the rendering of an outcome. That would make the component question answer itself and put the copy tables beside the renderers that print them. Not urgent — flagged as the structural pressure behind the emission split rather than as a defect in its own right.
SUMMARY: The core design lands well — a token-only key with the staleness rule single-sourced in `internal/hooks`, the snapshot-before-enumeration ordering made structural inside `CleanStale` rather than left to caller discipline, clean removal of the `@portal-id` machinery, and strong end-to-end coverage of the reboot and pane-move paths. The findings cluster on the observability seam and the type vocabulary: one sweep cycle's lines are now scattered across three log components by an injected logger, the `on-resume` event stayed an untyped literal the store itself now reaches for while the weaker `Via` concept got a closed enum, and the stand-down reason vocabulary is guarded three ways while carrying members no surface reaches.
