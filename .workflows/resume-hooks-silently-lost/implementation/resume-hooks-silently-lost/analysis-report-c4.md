## Summary

The hook machinery this work unit exists to fix lands well — the staleness rule, the id vocabulary, the snapshot-before-enumeration ordering and the lock bounds each have one home — and the cycle-4 agents found no defect in it. The findings that matter cluster elsewhere: two production defects reached through neighbouring doors (a saver-readiness barrier that fails open on a fixed 2s budget so a cold boot can proceed with no daemon, and a period-bearing session name that the capture loop silently drops from `sessions.json`), an observability seam that now scatters one sweep cycle across three log components, and a very large test-scaffolding residue where separately-executed tasks each re-authored the repo-wide source-scan driver, the build-constraint reader, the Cobra command drive and the hooks.json path composition rather than reaching for the shared primitive the work unit itself introduced. Two specification statements about the stand-down vocabulary are now false against the code.

## Spec Defects

### S1: The stand-down reason vocabulary is five in the specification and seven in the code, and a failed marker read no longer produces the same result as a set marker

- **Claim**: §5.4 (line 310): "The sweep declines to run for five distinct reasons … `restoring` for the marker, `lock-timeout` for §6.5's bound, `empty-pane-read` for the guard above, plus `store-read-failed` when the `hooks.json` load fails and `pane-read-failed` when the `list-panes` enumeration itself fails." Requirement table (line 504): "a failed marker read produces the same result as a set marker (§5.4)." Corrigendum 2026-09-01 (line 552): "all five reasons render a phrase on both surfaces."
- **Observed**: `cmd/run_hook_stale_cleanup.go:22-30` declares **seven** `skipReason` constants — the five named plus `marker-read-failed` and `sweep-failed` — and `skipReasons` (`:53-61`) enumerates all seven, with both phrase maps (`:81-100`) exhaustive over them. A failed marker read produces the same *posture* as a set marker but a different *phrase*: `could not read the restore marker` rather than the restore wording, on both the `--fix` line and the read-only diagnosis. Because `hook` and `doctor` are bootstrap-exempt and start no server, a read-only `portal doctor` on a machine with no tmux server running is the ordinary path into that branch, so the common user-facing line for that state is now the marker-read phrase. `sweep-failed` is a departure in kind rather than degree: it is never a decline (the sweep ran and failed), it is never logged under `clean-stale-skipped`, and the copy-uniqueness guard has to subtract it back out via `notStandDownReasons` to compensate for a member the type's own contract excludes. No corrigendum records either addition.
- **Read**: Split. **Spec stale** for `marker-read-failed`: the implementation's reasoning is sound and recorded in-source ("the server is routinely down when a user reaches for a diagnosis, and reporting that as a restore would assert something that is not happening") — the spec's own argument for naming the decline is that an operator greps one value to learn why, which a phrase that asserts a restore the user is not running defeats. That wants a corrigendum recording the split to six, the rationale, and the two rendered phrases on both surfaces. **Code wrong** for `sweep-failed`: it is a member of a closed vocabulary whose contract excludes it, and it is the reason the copy guard needs a subtraction list — Task 9 in the staging file proposes moving it out of `skipReason`, which would return the declared set to six and leave the vocabulary internally consistent. A sibling task (8-45) also touched this vocabulary, so one corrigendum should cover both rather than two.

### S2: The specification names `shellQuoteSingle`, a symbol that no longer exists

- **Claim**: §3.3 (line 162): "**`buildHydrateCommand`** (`internal/restore/session.go`) interpolates the key into `portal state hydrate --hook-key %s` through `shellQuoteSingle` and bakes it into a `respawn-pane -k` command line."
- **Observed**: `grep -rn shellQuoteSingle --include='*.go' .` returns nothing. The quoting rule was extracted into the stdlib-only leaf `internal/shellquote` and the function is now `shellquote.Single`; the decision the sentence records is retained and implemented byte-for-byte through the same substitution.
- **Read**: Spec stale — document drift only, no code change implied. The reference should read `internal/shellquote.Single`.
