- `internal/tui/model.go:2356-2363` **states a load-bearing invariant that is false, and the code at 2370-2379 depends on it.** The comment claims "every route off a page is a keypress, and an actionable keypress clears the flash before it dispatches… so no page is ever entered carrying a band its list was not sized for", and line 2369 claims "the post-load warnings band is raised after `transitionFromLoading` has landed a page". **Neither holds on the cold concurrent-bootstrap route:**

  1. `model.go:2452` — `transitionFromLoading` sets `PageSessions` and returns early when `progressReceiver != nil`, deliberately leaving `defaultPageEvaluated` false. It has **NOT** landed the final page.
  2. `model.go:2649` / `2692` — `surfaceBufferedWarnings()` then raises the flash (page = `PageSessions`, so `m.sessionList` is resized) batched with `refetchSessionsAfterRestore()`.
  3. `model.go:2623-2624` — the refetch's `SessionsMsg` sets `sessionsLoaded = true` and calls `evaluateDefaultPage`, which at `2191` flips to **`PageProjects`** when the restored session list is empty. This is a **message**, not a keypress, so the flash-clear at `2997` never runs and the flash is still live (the 3 s tick has not fired — the refetch resolves in milliseconds).
  4. Nothing resizes `m.projectList` on that path (`applyProjectListSize` is only reached from `WindowSizeMsg`, `ProjectsLoadedMsg` and `rebuildSessionList`'s Sessions sibling), so `viewProjectList` composes header + slot(2) + a list still budgeted for no band + footer = **termH + 2**. The outer fill pads, it does not clip, so the frame overflows and the terminal scrolls the title off the top — **the exact failure class CLAUDE.md records as the original cursor-invisible incident.**

  Reachable on: cold TUI boot + non-empty bootstrap warnings + zero sessions after restore — i.e. a degraded or first-run install, which is where a broken frame costs most. **Before this task the flash never rendered on Projects, so the overflow is new.**

  FIX (recommended): make `resyncActivePageLayout` re-size **both** lists — drop the `PageProjects` early-return and call `applySessionListSize` and `applyProjectListSize` unconditionally (both after the existing zero-dimension guard, which must stay). This is a strict superset of the pre-task behaviour plus the new Projects coverage, is idempotent (each wrapper reserves its own page's arbiter height from current state), and costs two cheap band renders on a rare event. Then correct the doc comment: state that both are sized because a page can also be entered by a **message** (`evaluateDefaultPage` on the cold route), not only by a keypress, and drop the "budget rows on a page nobody is looking at" rationale — an unused budget is free, an unsized entry is a frame overflow. Add a test alongside `TestProjectsFlash_SurvivesWindowSize` that raises a flash on `PageSessions`, flips to `PageProjects`, and asserts `m.projectList.Height()` equals base − `projectBandHeight()`.

  ALTERNATIVE: keep the active-page-only resync and instead re-size at the flip site (a resync call at the end of `evaluateDefaultPage`, `model.go:2192`). More surgical and keeps the "only the page you're on" story, but it puts the invariant back on a list of flip sites that must each remember to call it — the same drift risk the codebase eliminates elsewhere by measuring off a single slot. The both-lists fix is recommended.
