- FINDING: Theme panel header costs five rows, not the specified two — the minimum-height floor is ~3 rows stricter than §9.8's arithmetic
  SEVERITY: medium
  FILES: internal/tui/theme_panel_geometry.go:89-109, internal/tui/theme_panel_geometry.go:165-167, internal/tui/theme_panel_render.go:63-70
  DESCRIPTION: §9.1 fixes the panel header as the `Themes` label "followed by a one-row `border` rule" and states "The header therefore costs **two rows**, which is what §9.8's minimum-height rule (header + footer + one row) resolves against." The implementation instead measures the panel's header region off the *page's* chrome: `themePanelHeaderRows() = themePanelHeaderLabelRow() + sectionHeaderBlockRows()`, where `themePanelHeaderLabelRow()` is `lipgloss.Height(renderHeaderBlock(...))` = band + rule + blank = 3, and `sectionHeaderBlockRows()` = 2 — so the header block is **5 rows**, of which only two carry content (`themePanelHeaderBlock` writes the rule at index 1 and the label at index 3; the other three are deliberately blank), and the rule renders *above* the label rather than below it. Two consequences follow. (a) `themePanelMinHeight` = 5 + footer(4) + message(1) + body(1) = 11 (12 with the pinned `⚠ dir unreadable` row) against the specified 2 + 4 + 1 + 1 = 8, so `themePanelFloor` refuses `t` and force-closes on resize across a ~3-row band of content heights where §9.8 says the panel must still degrade and render. §9.8's whole doctrine is "degrade, don't refuse … refuses only when even the minimum panel cannot render", and here the refusal is driven by rows the panel deliberately draws nothing in. (b) §9.1's header composition (label then rule) is inverted. The page-alignment rationale is argued at length in-source (`themePanelHeaderBlock`, `themePanelBlock`) and is defensible — the panel is composited at content Y=0 and reads as a surface inside the content region — but it silently re-decides a number the spec pinned and tied to a user-visible refusal threshold.
  RECOMMENDATION: Confirm the page-aligned header is the intended shape (the reference frames are the arbiter), and if so, exclude the blank alignment rows from the floor so the refuse threshold matches §9.8's stated composition — the panel can render its list body beside the page's header band, since it is an opaque layer. If the inflated floor is intended, record the deviation explicitly so §9.1's "costs two rows" claim and §9.8's arithmetic are not left stale in the specification.
