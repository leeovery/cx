Mutating `classify`'s `result, rejection := l.LoadFile(path)` (`internal/theme/enumerate.go:119`) to `Loader{}.LoadFile(path)` leaves the entire package suite passing. That silently disables rung 2 at the enumeration entry point, which is §5.4's no-shadowing property — the one rule the spec calls a hard constraint ("if a user file could shadow the built-in that is the fallback, the fallback itself could be broken. That must be impossible"), since a shadowing drop-in would enumerate as a valid, selectable panel row. It is also the only rejection reason whose entry keeps a slug that is untested here.
  FIX: add `TestEnumerate_AppliesTheInjectedReservedSlugs` to `internal/theme/enumerate_test.go`, following the existing shape — stage `writeTheme(t, dir, "nord.theme", themeLines())`, call `theme.Loader{ReservedSlugs: map[string]struct{}{"nord": {}}}.Enumerate(dir)`, then `requireRejectedEntry(t, entry, theme.ReasonReservedName)` plus an assertion that `entry.Slug == "nord"` (the "only a bad name costs an entry its slug" invariant, for the one reason class where it is currently unpinned). While there, consider extending `TestEnumerate_CaseInsensitiveExtensionVisibleThenBadName` (or adding one case) for the *slug* bad-name cause — e.g. `Nord.theme` (legal extension, illegal stem, `BadNameSlug`) — so both causes of the empty-slug rule are covered at this level, not just the extension one.
  CONFIDENCE: high

- `internal/theme/enumerate.go:174-184` — `notADirectory` synthesises `&fs.PathError{Op: "readdir", …}`, and the comment asserts "It is shaped exactly as the OS would have shaped it". The type and errno are right, but the verb is not: Go's `os.ReadDir` opens with `O_DIRECTORY` (`os/file_unix.go:291`, `file_windows.go:166`), so the real error for this exact condition is `open <path>: not a directory` with `Op: "open"` — verified on this machine. `readdir` is a verb no code path in Go produces, and `Rejection.Detail` is the §14A "OS error verbatim" field, so the one fabricated part is the part the field's contract is about.
  FIX: change `Op` to `"open"` and soften the comment to say the error is *reconstructed* in the shape Go's own `ReadDir` would have produced (type, verb, errno), since the stat leaves no error to carry. One-word change, keeps `errors.Is(…, syscall.ENOTDIR)` and the platform-independent verdict the task asked for.
  ALTERNATIVE: drop the synthesis and let the doomed `os.ReadDir` produce the error (the `!info.IsDir()` branch becomes redundant on POSIX, where `open` reliably returns `ENOTDIR`). Genuinely verbatim and drops the `syscall` import, but it deviates from the task's prescribed `Stat`-decides-the-verdict structure and makes the verdict depend on `ReadDir` behaviour. Reviewer recommends the one-word fix.
  CONFIDENCE: medium

Cosmetic; no behavioural difference for a bare `os.Stat` error.

That follows the task's instruction literally and the spec does not discriminate, but it is worth carrying into Phase 8's doctor/log work as a known accepted behaviour.
