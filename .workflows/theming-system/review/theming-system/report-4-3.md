SPEC CONTEXT:
§13.4 ("The swap-and-diff completeness guard") specifies the feature's central completeness mechanism: render every fixture under theme A, swap live to theme B through the production entry point, render again, and scan for surviving A values. The spec is unusually prescriptive about *construction* rather than just assertions, because all three failure modes are silent: naming fixtures instead of enumerating them, using two shipped themes (a shared hex renders identically either side of the swap and covers nothing), and searching for the wrong representation (assertion 1 is a negative and passes vacuously). It mandates: enumeration over the harness's fixture set; two synthetic themes with all 38 values unique, constructed in-test (§3.2 makes `Theme` an ordinary struct so no loader is needed); comparison against the rendered SGR form, not hex; a truecolor render; a live mutation of ONE already-rendered model through the production swap path (two models would each style correctly at construction and pass green while live swap is broken — §11.2's cached-style class is assigned once at construction); union-not-per-fixture for assertion 2; colourless fixtures excluded; unit lane. §11.3 adds that `View().BackgroundColor` is a per-frame declarative assignment Bubble Tea diffs into OSC 11, which is not part of `Content` and so needs its own check. Assertion 3 (every token exercised by some fixture) is explicitly deferred to task 4-4.
