TASK: theming-system-8-4 — Row Composition And The Invalid-Row Treatment (Phase 8: The Slide-Over Panel)

ACCEPTANCE CRITERIA (from the plan task):
1. Every row renders exactly one line — `lipgloss.Height(row) == 1` — for every combination of (valid/invalid) × (badge/no badge) × (short/long label) at the preferred and minimum widths.
2. An invalid row with no badge renders ⚠, label and reason; the same row with a badge renders ⚠, label and badge, and the reason is absent.
3. A label longer than the remaining budget is truncated with `…` and never falls below three visible characters plus the ellipsis.
4. An invalid label renders in `text.subtle` while its ⚠ and reason render in `accent.attention` — asserted as distinct SGR runs on the same line.
5. `text.faint` appears nowhere in a panel row's output.
6. All seven §6.2 reason labels render verbatim, each prefixed `⚠ `; the count is asserted.
7. A `bad name` row is labelled by its filename and a `reserved name` row likewise, both via `Row.Label()` with no second derivation in the delegate.
8. A `reserved name` row renders no ● even when its slug is the persisted one, while the built-in it collides with renders the badge — asserted on two adjacent rows of the same union.
9. A valid row is `text.primary` and a built-in is byte-identical to a valid drop-in with the same label and badge state.
10. The cursor row carries the `bg.selection` tint across the full row width with an `accent.primary` ▌ and a `text.on-selection` label.
11. Rendering the same item under two different `Theme`s produces different colour output with no cached-style carry-over.
12. Under `Colourless` the row emits no background SGR and no hue, and still carries ⚠, ● and ▌ as glyphs.
13. `internal/tui`'s colour-literal guard passes — the delegate contains no hex literal.

STATUS: complete

SPEC CONTEXT:
Specification §9.5 ("Row rendering and markers", lines 1074–1123) fixes the one-delegate-line invariant `bubbles/list` pagination rests on, and the four-element competition for the ~24–30 column panel: (1) the ⚠ glyph, always on an invalid row, costing two columns; (2) the right-aligned ● badge, which outranks the reason because §9.4 exists so the marker always has a home; (3) the label — slug, or filename for a `bad name`/`reserved name` row — truncated with `…` down to three visible characters plus the ellipsis; (4) the terse reason, right-aligned and the first element dropped when a badge competes for the same edge. §9.1 pins the invalid label to `text.subtle` explicitly *not* `text.faint` (§13.5 floors `text.faint` below the UI threshold so it can never carry content), and keeps the ⚠ and its reason on `accent.attention` so the invalidity signal stays legible on a deliberately dimmed row. §11.2 makes the panel the worst case of the cached-style class — its delegate must re-derive per frame from the previewed theme, since the theme changes on every arrow keypress. §6.2's seven reason strings are user-facing copy rendered verbatim (`internal/theme/reason.go:12-20`), with `not found` the one reason outside the loader ladder. §1.4 defers panel search, which is why the panel list disables filtering rather than wiring `FilterValue`.

- Notes:
  - **Layout interpretation (not drift).** The ⚠ is rendered on the *trailing* (right-aligned) side of the row, fused with the reason (`compose:91-99`), rather than immediately after the cursor column. §9.5 states positions only for the badge and the reason ("right-aligned"); it fixes the ⚠ as a *priority* and a two-column cost, not a position. The chosen placement is the one that preserves the shared label left edge across valid and invalid rows (a leading ⚠ would indent invalid labels two columns further than valid ones). The two committed panel reference frames (`testdata/vhs/reference/theme-panel-adaptive-pair-mv.png`, `theme-panel-constant-previewing-mv.png`) contain no invalid row, so the design export neither confirms nor contradicts it. Recording the reading, not flagging it.

This is correct, not drift: because the label budget is clamped to the floor, measuring a sub-floor label at its natural width would admit a reason and then push the composed row past the panel's inner width, spilling the slide-over out of its composite. The in-source comment states exactly this, and `TestThemeRow_ShortLabelDropsTheReasonRatherThanOverflow` pins it.
